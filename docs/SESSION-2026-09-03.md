## What happened, in order

### 1. Contract review → 5 app defects

Read the published *Delivery Partner API v1.0* against the code. Found and fixed:

- `currency` typed `string`, is an object → cash rendered `[object Object] 12.50`. Now `OMR 12.500` using `currency.decimals`.
- Times shown in raw UTC → 4 h early in Muscat. Now converted via the returned `timezone`.
- `confirm_return` was the hero button on a `returning` job and did nothing.
- `POST /duty` missing entirely — jobs list could be empty forever with no explanation.
- Orders collapsed to one job; a rider holding two couldn't reach the second.
- *(found while testing)* Screen state leaked between jobs — a delivered job blanked the next one's buttons.

### 2. Two competing API designs → one contract

A second brief proposed `/api/driver/*`, `start-transit`, SMS, and showing the pickup OTP to the rider. Mapped it onto the live `/api/delivery/*` endpoints instead: **six additions** rather than a rewrite.

Flagged **D1** (pickup OTP shown to the rider) as a security decision, not a preference — a code on the rider's phone proves the rider has a phone, not that the shop handed over the parcel. Backend agreed; it stays shop-side.

### 3. Their live test run → 3 more defects

Their 40-call capture exposed what no amount of reading could:

- `GET /orders/{id}` **nests under `order`** — every job screen said "That job is gone".
- `failed` is a delivery status that appears in no document.
- `/pickup/request-otp` returns `success: false` while still issuing the code — the resend button looked broken.

Also: the mock was hiding all three, because it was built on the app's own assumptions. Corrected to mirror the server.

### 4. First real calls

Tunnel and token worked — the first successful real calls this project had made.

**N2 shipping had broken the app:** `shop` became an object and the app rendered it raw → React Native throws "Objects are not valid as a React child". Jobs list and job screen both crashed on live data. Fixed with `shopName()` accepting either shape, so their rollout and any cached response both work.

### 5. Their reply → 10 items answered

- **Item 3, terminal jobs leaking into `/orders`:** confirmed as a real bug — *"You were right and my 'verified' was wrong. I checked delivered only."* Filter was `!= 'delivered'`. Fixed, verified live.
- **Item 4, rial vs baisa:** **rial.** `amount_to_collect = sale.order.amount_total` in the order's currency, checked against four live jobs. The one question that could have cost a customer money — closed.
- **Item 8, coordinates:** never populated, nothing geocodes. *"Stop drawing the map."*
- **Item 1, base URL:** tunnel stays dynamic by design. Their ask — read it at runtime — was already satisfied by `config.ts`.
- **Item 2, WhatsApp 403:** fixed. Split `web.base.url` from a new `public_base_url`. Real codes now deliver.
- **Item 5:** auth errors now carry `code: "unauthorized"`.
- **Item 7:** `failed` is legacy only — nothing sets it since 19.0.6.0.0.
- **Both our offers built:** 60 s cooldown via `retry_after_seconds`; reason list adopted verbatim.

### 6. Acted on the reply

- **Deleted `StaticMap`** — with coordinates always `null`, it could only render its empty-state panel: 40% of the en-route screen as a permanent grey rectangle. Navigation is by written address, always.
- **Built the reason picker** — 8 agreed codes (`customer_absent`, `customer_refused`, `address_wrong`, `address_unreachable`, `payment_refused`, `damaged`, `vehicle_problem`, `other`) plus free text behind "Something else". Replaces a hardcoded `'Reported from the app'`.
- **Resend button counts down** on `retry_after_seconds` instead of silently doing nothing for a minute.
- **Mock re-synced** to the fixed terminal-state filter; three test assertions that encoded the bug were inverted to assert the fix.
- **Fixed copy:** the delivery code arrives by **WhatsApp**, not SMS.

### 7. Browser walk rebuilt

It was testing the old "Big Type" design; Glass Light had replaced it. Rewritten:

- Drives the duty `Switch` (was a text button)
- Targets "Open order" per card — first attempt opened the *wrong job* because the ancestor walk climbed past the card into the scroll container
- Handles both `OtpInput` (pickup) and the hidden `opacity: 0` input inside `OtpBoxes` (delivery)
- Picks a reason on return
- Dropped the "no shadows" rule — Glass Light uses shadows by design
